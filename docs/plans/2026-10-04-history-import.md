# Импорт истории и исходная статистика

## Результат

Firefox-расширение принимает `games_raw.ndjson` и необязательный `rating_history.json`, показывает предварительный отчёт и сохраняет историю после подтверждения. Статистика разделена по bullet, blitz и rapid; график показывает выбранный рейтинг и период данных. Повторный импорт не добавляет одинаковые партии. Отметки тренировок сохраняются отдельно.

## Данные

- Профиль — `sebajun777`, даты тренировок — `Asia/Bishkek`.
- Исходный файл содержит 6 430 строк / 6 429 уникальных rated standard партий. Внутри — один точный повтор `RflOKJvH`.
- Контроли этого этапа: bullet, blitz, rapid. Другие контроли, casual, варианты и незавершённые партии пропускаются с явным числом в отчёте.
- Проверяется ID, принадлежность профилю, типы и временные поля. Ошибка JSON или непригодная структура останавливает весь импорт до записи; выводится номер строки.
- Даты партий должны представляться как YYYY-MM-DD по времени Бишкека; выход за четырёхзначный год отклоняется до сохранения.
- Противоречивые повторения одного ID отклоняются. Повтор точной нормализованной записи считается дубликатом.
- В базе хранится компактная запись партии с результатом, цветом, рейтингами, дебютом, ходами и собственными сводными показателями анализа. Полный исходный файл остаётся отдельным источником; часы и покадровые оценки этого этапа не используются.
- NDJSON: максимум 20 МиБ и 100 000 непустых строк. JSON рейтингов: максимум 1 МиБ. Поля рейтинга без значения остаются неизвестными.
- Рейтинговый JSON использует нулевой номер месяца. Поддерживаются Bullet, Blitz, Rapid, Puzzles. Прочие серии игнорируются; точки проверяются, сортируются и не дублируются по дате. Разные значения одной даты отклоняются.

## Хранение и интерфейсы

IndexedDB v2 добавляет `games`, `ratings`, `historyMeta` к прежнему `journal`. Существующие отметки v1 сохраняются. Партии индексируются по `id`, `speed`, `createdAt`. Фоновая страница остаётся владельцем изменений; разбор файлов и проверки происходят до транзакции.

Новые методы repository:

- `readHistory()` → `{ games: Game[], ratings: RatingSeries[], meta: object|null }` в одном согласованном чтении.
- `importHistory({ games, ratings, meta })` → `{ added, existing, total }`; вставка отсутствующих game ID, замена явно переданных рейтинговых серий и metadata одной транзакцией. `ratings: null` означает сохранить прежние серии. Исторический импорт не переписывает существующие партии и не трогает journal.

`createHistoryService({ repository, now = () => new Date() })` обрабатывает:

- `history.getOverview` → `Overview`.
- `history.previewImport` с `{ gamesText, ratingsText?, sourceName }` → `ImportPreview` без записи.
- `history.import` с теми же полями → `{ overview, report: { rows, unique, duplicates, skipped, added, existing, total } }` после успешной записи.

Фон отправляет привычный envelope `{ ok, data/error }`. `training.*` продолжает работать без изменения схемы snapshot. Большие партийные записи не пересылаются popup.

В ответе сервиса `report.total` соответствует возвращённому `overview.totalGames`; `added` и `existing` относятся к отдельному пакету. Поэтому два параллельных импорта могут показать уже объединённую историю с согласованным общим счётчиком.

`Game`: `{ id, username, speed, createdAt, lastMoveAt, status, rated: true, variant: "standard", color, result: "win"|"loss"|"draw", rating: number|null, ratingDiff: number|null, opponent: { id, name, rating }, opening: { eco, name }|null, moves: string, analysed: boolean, playerAnalysis: { acpl, inaccuracy, mistake, blunder }|null }`.

`RatingSeries`: `{ name: "Bullet"|"Blitz"|"Rapid"|"Puzzles", points: [{ date: "YYYY-MM-DD", rating: number }] }`.

`Overview`: `{ totalGames, firstGameAt: number|null, lastGameAt: number|null, importedAt: string|null, sourceName: string|null, groups: [{ speed, games, wins, losses, draws, analysed, winRate: number|null, lastRating: number|null, ratingDate: string|null }], ratings: RatingSeries[] }`.

`ImportPreview`: `{ rows, unique, duplicates, skipped, ratingPoints, firstGameAt, lastGameAt }`.

## Экран и резервные копии

Dashboard получает отдельную карточку истории: выбор NDJSON и необязательного JSON рейтингов, отчёт до сохранения, понятные ошибки и итог повторного импорта. Таблица показывает результаты и покрытие анализа; график — одну рейтинговую серию с её датой, без смешения разных шкал. При отсутствии данных показывается пустое состояние. Исторический компьютерный анализ не считается собственным разбором.

Версия backup тренировок остаётся 1 и содержит журнал отметок. В интерфейсе это явно названо копией **отметок тренировок**. Историю партий можно повторно импортировать из исходных файлов; экспорт всей базы будет отдельным расширением формата. Старые копии принимаются и не удаляют историю партий.

## Проверки

1. Проверки парсера: строка ошибки, профиль, дубликаты/противоречия, границы размера, ничьи и незавершённые игры; нулевой месяц и неверные даты рейтингов.
2. Проверки базы: переход v1→v2 сохраняет journal; одновременные импорты не дублируют ID; сбой отменяет весь пакет; отсутствие нового рейтингового файла сохраняет прежние серии.
3. Реальный датасет: 6 429 партий; bullet 5 917, blitz 345, rapid 167; 266 с анализом. Повторный импорт добавляет 0.
4. Статистика: результаты 3 143 / 3 108 / 178; последние рейтинги снимка 2 143 / 1 707 / 1 823. Данные показывают март 2026, а не текущую форму.
5. Старые тесты тренировок сохраняются; UI не сообщает успех до commit, ошибки не стирают предыдущий обзор.
6. Проверка addon, упаковка только `extension/`, учебный урок по импорту. Реальные диалоги файлов и отображение Firefox проверяются вручную, если подключённый браузер недоступен.
