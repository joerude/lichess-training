# Свежие партии из Lichess

## Результат

Версия 0.3.0 добавляет обновление по кнопке и число завершённых rated standard партий bullet/blitz/rapid за сегодня по Бишкека. Партии добавляются и обновляются по game ID; отметки задач остаются ручными. Загрузка продолжает незаконченный цикл после закрытия вкладки. Последнее полностью завершённое обновление показывается отдельно от сохранения очередной порции.

Обучение: путь кнопка → разрешение → HTTP/NDJSON → проверка → транзакция, затем небольшое самостоятельное изменение. API не требует токена для публичных партий этого профиля. OAuth, игровые задания с нормами, XP и периодические фоновые обновления остаются следующими этапами.

## Сетевой контракт

`createLichessClient({ fetchImpl = globalThis.fetch, now = () => Date.now(), timeoutMs = 30000 })` возвращает `fetchGamesPage({ since, until, max = 200 }) → { records, rows }`.

- GET `https://lichess.org/api/games/user/sebajun777` с `since`, `until`, `max`, `sort=dateAsc`, `ongoing=true`, `finished=true`, `moves=true`, `opening=true`, `clocks=false`, `evals=true`, `accuracy=true`; Accept `application/x-ndjson`, credentials `omit`.
- Параметры rated/perfType не передаются: используется последовательная выгрузка по времени начала. Фильтр применяется локально. Окно `[since, until)` фиксируется для всего цикла. Следующая порция начинается с последнего createdAt включительно; ID устраняет повтор на границе.
- Запросы выполняются последовательно. HTTP 429 запрещает повтор минимум на 60 секунд, учитывается более долгий Retry-After. Ошибка содержит `retryAt`; сервис сохраняет паузу в базе. Не выполняются автоматические повторные сетевые запросы после ошибки.
- Таймаут включает чтение потока. Порция ограничена 200 непустыми строками и 8 МиБ UTF-8; допускаются keep-alive пустые строки, разделённые UTF-8 символы и последняя строка без LF. Повреждённый ответ отклоняется целиком до записи.
- Firefox запрашивает только optional host `https://lichess.org/*` и optional data collection `authenticationInfo` для передачи имени профиля. Обе проверки выполняются перед запросом; отказ сохраняет локальные функции. Запрос разрешения запускается непосредственно обработчиком кнопки.

## Покрытие и прогресс

Начальная нижняя граница — последняя известная партия минус семь дней; если истории нет, последние 30 дней. Она фиксируется при первой записи состояния обновления, включая сохранение паузы 429, и не сдвигается в следующих циклах. Это явное окно обновления, не доказательство полноты партий, начавшихся раньше него. Старую историю даёт импорт исходного датасета; его стоит загрузить перед первым обращением к API.

Каждый новый цикл заново просматривает всё это окно. Поэтому партия, начавшаяся внутри окна и завершённая после прежнего обновления, попадёт в следующую сверку. После первой порции временная верхняя граница сохраняется; новые игры после неё попадут в следующий цикл. При 200 строках курсор сдвигается на последний createdAt, при меньшем числе цикл завершён. Если заполненная порция не продвигает дату, операция отклоняется, не объявляя полноту и не пропуская равные времена.

Кнопка обрабатывает до пяти порций подряд, показывает результат каждой сохранённой порции и при необходимости предлагает продолжить. Остановка между порциями не отменяет уже сохранённое. Закрытие экрана также не теряет сохранённый курсор.

`SyncState`: `{ revision, coverageStart, cycleUntil: number|null, nextSince: number|null, completedUntil: number|null, lastSuccessAt: string|null, retryAfter: number|null }`.

`SyncSnapshot`: `{ overview, sync: SyncState, today: { date, groups: [{ speed, games }] }, permissionGranted }`.

`createSyncService({ repository, lichess, canAccess, now = () => new Date() })`:

- `sync.getSnapshot` → SyncSnapshot, без сети и изменения программы.
- `sync.nextBatch` → `{ snapshot: SyncSnapshot, report: { rows, eligible, skipped, added, updated, total, hasMore } }`.
- Одновременные nextBatch в одном фоновом контексте получают одну выполняющуюся операцию. Revision защищает от записи устаревшего курсора другим контекстом.

## Хранение

Схема остаётся IndexedDB v2: новый ключ `sync` в historyMeta. `readSyncHistory()` читает games/ratings/import metadata/sync одним readonly transaction; `readHistory()` сохраняет прежний интерфейс. `saveSyncBatch({ games, sync, expectedRevision })` обновляет партии и состояние одной транзакцией, возвращая `{ added, updated, total }`. При несовпадении revision пакет отклоняется до записи.

Тот же ID должен иметь прежние username, createdAt, speed, rated, variant и color. Иначе пакет ошибочен. Более старый lastMoveAt не заменяет запись. Новые известные рейтинги, ходы и анализ обновляют партию; пропущенные поля не стирают имеющиеся сведения. Одинаковая повторная запись не увеличивает updated. Исторический импорт остаётся insert-only, backup v1 — только отметки тренировок.

API сначала проверяет базовые поля и границы времени всех строк для пагинации. Casual, другие варианты/контроли и незавершённые партии отбрасываются до проверки подробных полей соперника; так партии с анонимным игроком/компьютером не ломают загрузку. Подходящие партии проходят существующий нормализатор и проверку профиля. Противоречащие повторы подходящего ID отклоняются.

График сохраняет исходные точки рейтингового JSON и добавляет известные дневные значения после последней исходной даты. Puzzles остаётся исторической серией до подключения задач отдельно. Сегодняшний счётчик относится ко дню начала партии, а не точному времени её окончания.
