# Автоподсчёт задач и прогресс в popup (0.4.1)

Дата: 2026-10-12. Статус: дизайн согласован с пользователем, ждёт просмотра спецификации.

## Проблема

В 0.4.0 задание «10 задач» отмечается только вручную. Пользователь решил несколько пазлов на lichess.org/training, popup показал «Сегодня ещё не отмечено», и было непонятно, сколько осталось. Нужен прогресс «4/10» с фразой поддержки и автоматический зачёт при достижении нормы.

## Решения

| Вопрос | Решение |
|---|---|
| Источник данных | Публичный профиль `GET https://lichess.org/api/user/sebajun777`, поле `perfs.puzzle.games` (проверено 2026-10-12: `{games: 894, rating: 1861, …}`). Без OAuth, cookies и токена. |
| Когда запрашивать | При открытии popup и по кнопке ↻, не чаще одного раза в 60 с. Перед открытием lichess.org/training кнопкой «Открыть задачи». Фонового опроса нет. |
| Где показывать | Только карточка `#today-card` в popup. Основной экран видит результат через общие данные. |
| Зачёт задания | Автоматически, как только счёт дня достигнет нормы. Ручная кнопка остаётся. |

Отклонено: content script на lichess.org/training (новое разрешение, хрупкая зависимость от DOM Lichess), OAuth `puzzle:read` (этап 5), фоновый таймер (запросы без действия пользователя), лента `/api/user/{name}/activity` (дни по UTC, а у проекта дни по Asia/Bishkek; граница 06:00 местного времени).

## Ограничения, о которых пользователь знает

- Пазлы засчитываются, только если в этом Firefox выполнен вход в Lichess. Анонимные задачи в счётчик профиля не попадают.
- Счётчик профиля считает все попытки, а не только успешные.
- Пазлы, решённые до первого наблюдения за день, в счёт не попадут. Поэтому «Открыть задачи» сначала снимает счётчик, и карточка показывает «счёт с ЧЧ:ММ».

## Данные

Новый ключ `historyMeta['puzzles']`, схема IndexedDB не меняется (версия 2):

```js
{ date: 'YYYY-MM-DD',   // день по Asia/Bishkek
  baseline: 894,        // счётчик при первом наблюдении дня
  latest: 898,          // последний прочитанный счётчик
  baselineAt: ISO,      // время первого наблюдения
  observedAt: ISO }     // время последнего успешного запроса
```

Правила:
1. Записи нет или `date` не сегодня: `baseline = latest = прочитанное`, `baselineAt = observedAt = сейчас`.
2. Тот же день: обновляются `latest` и `observedAt`.
3. Если `latest < baseline` (сброс или ошибка данных): `baseline = latest`, счёт 0.
4. `solved = max(0, latest − baseline)`.
5. Повторный запрос раньше чем через 60 с после `observedAt` не идёт в сеть, возвращается сохранённое.

Запись в `historyMeta['puzzles']` и автоотметка дня выполняются в одной транзакции (по образцу `transactPractice`). Наблюдение без автоотметки пишется отдельной короткой транзакцией.

### Автоотметка

День журнала (`journal.state.days[]`) получает два необязательных поля:
- `source: 'manual' | 'auto'`: кто поставил `completedAt`. Отсутствие поля означает `'manual'` (совместимость с 0.4.0).
- `autoSuppressed: true`: пользователь снял автоотметку сегодня; автозачёт в этот день больше не ставит её.

Когда `solved >= target` (норма дня из `tasksOn`), `completedAt == null` и нет `autoSuppressed`, ставится `completedAt = сейчас`, `source = 'auto'`. Награда начисляется существующим `reconcilePractice` со стабильным ID `${startedOn}:${date}:puzzles`, поэтому повтора не будет. Снятие отметки вручную при `source === 'auto'` ставит `autoSuppressed: true`.

Нормализация дня (`extension/core/training-engine.js:85-89`) сейчас возвращает только `{date, target, completedAt}` и молча отбросит новые поля. Её нужно расширить: `source` допускает только `'manual' | 'auto'`, `autoSuppressed` только `true`, а при `completedAt === null` поле `source` не хранится. `setCompletion` для ручного действия пишет `source: 'manual'`.

Backup v2: валидация должна принимать оба новых поля и восстанавливать их. Копии 0.4.0 без них остаются валидными.

## Сеть

Новый метод в `extension/data/lichess-client.js`, например `fetchPuzzleCount()`:
- использует ту же очередь, таймаут (30 с), паузу после 429 (`Retry-After`, минимум 60 с), `credentials: 'omit'`, `redirect: 'error'`;
- `Accept: application/json`, ограничение тела (достаточно 1 MiB);
- возвращает целое `perfs.puzzle.games` или ошибку `no-data`, если поля нет или оно не целое ≥ 0.

Перед запросом проверяется optional permission `https://lichess.org/*` через существующий `canAccess`. Без разрешения запроса нет.

## Сообщения

- `puzzles.refresh` → `{ status, date, solved, target, baselineAt, observedAt, completed, source }`. Может пойти в сеть (с учётом 60 с). Выполняет автоотметку.
- `status`: `'ok' | 'no-permission' | 'offline' | 'rate-limited' | 'no-data'`. При ошибке возвращаются последние сохранённые числа, если они за сегодня.

Popup вызывает `puzzles.refresh` при открытии, по ↻ и в обработчике «Открыть задачи» до `tabs.create`. Ошибка запроса не мешает открыть вкладку.

## Интерфейс popup

```
СЕГОДНЯ                   12 октября
4 / 10 задач
████████░░░░░░░░░░░░
Так держать — осталось 6
счёт с 09:14 · обновлено 10:02
[ Открыть задачи ↗ ]
[ Отметить вручную ]
```

- Полоса: `<progress max=target value=min(solved,target)>` с подписью для экранных читалок.
- Склонение: существующая `puzzleNoun`.

| Состояние | Фраза |
|---|---|
| 0 | «Начнём — N задач на сегодня» |
| 1 … ⌈N/2⌉−1 | «Хорошее начало — осталось K» |
| ⌈N/2⌉ … N−1 | «Так держать — осталось K» |
| = N | «Норма выполнена! +20 XP» |
| > N | «Сверх нормы: M задач» |
| `no-permission` | «Автоподсчёт выключен: подключите Lichess на основном экране» |
| `offline` / `rate-limited` / `no-data` | «Нет данных Lichess — можно отметить вручную» |

N — норма дня, K — сколько осталось, M — решено. Для нормы 10 границы те же, что согласованы: 1–4 и 5–9. Фраза выбирается чистой функцией, которую легко тестировать.

## Тесты

- Клиент: успешный разбор; нет `perfs.puzzle`; нецелое значение; таймаут; 429 и пауза; без разрешения запроса нет.
- Подсчёт: первое наблюдение; тот же день; новый день; счётчик уменьшился; ограничение 60 с.
- Автоотметка: пересечение нормы ставит `source: 'auto'` и одну награду +20; повторные refresh не удваивают; ручное снятие ставит `autoSuppressed`, и следующий refresh отметку не возвращает; ручная отметка до нормы не меняется.
- Backup v2: экспорт/импорт с новыми полями; копия 0.4.0 без них импортируется.
- Фразы: все строки таблицы, нормы 1, 10 и 11.
- Ручная проверка в Firefox: войти в Lichess, открыть popup (0/10, «счёт с …»), решить 2 задачи, через минуту открыть popup → 2/10.
