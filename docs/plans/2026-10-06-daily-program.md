# Ежедневная программа, разборы и награды

Версия 0.4.0. Firefox, ES modules, без новых зависимостей. Исходный датасет и существующие отметки сохраняются. Главная учебная тема — стабильные ID и атомарное сохранение связанных данных.

## Поведение

Подтверждён шаблон: 5 Bullet, 5 Blitz, 10 задач и 1 собственный разбор ежедневно. Rapid по умолчанию отключён. Партии считаются из сохранённых завершённых rated standard игр по дню начала в Asia/Bishkek. Задачи подтверждаются прежней ручной отметкой. Разбор требует сохранённой заметки к известной завершённой партии; компьютерный анализ сам его не выполняет.

Новая программа начинается в день первого открытия программы или нового интерфейса тренировок. Старые отметки и мартовский датасет не дают награды за дни до этого начала. Существующая сегодняшняя цель задач наследуется из старого журнала. Изменения норм создают или заменяют правила на завтра, сохраняя сегодняшний и прошлые дни. Допустимы 0–100 игр каждого контроля, 1–500 задач и 0–10 разборов.

За каждое выполненное задание — 20 XP, сверх нормы дополнительных наград нет. Награда имеет ID `startedOn:date:taskId`. Повторное открытие, импорт и обновление не удваивают её. Ручные награды задач/разборов пересчитываются при отмене отметки или удалении заметки; повторное выполнение возвращает одну награду. Награды за игры сохраняются как полученные достижения, включая восстановление копии без истории партий. Уровень вычисляется из суммы наград: `1 + floor(XP / 100)`.

Одна заметка на game ID; редактирование сохраняет первоначальный день разбора. Новый разбор старой партии датасета засчитывается в день сохранения. Заметка непустая, максимум 4 000 байт UTF-8; лимит 1 000 заметок. Оптимистическая версия заметки защищает правки в двух окнах. Удаление требует текущей версии. После восстановления заметку можно редактировать, даже если её партия ещё не импортирована.

Неполная загрузка API обозначается рядом с игровыми целями. Уже известное число >= цели доказывает выполнение; число ниже цели не доказывает отсутствие других игр. Новая неделя программы и старый календарь отметок задач показываются с разными подписями.

## Данные и интерфейсы

IndexedDB остаётся версии 2. В store `journal` добавляется ключ `practice`; прежний `state` сохраняет свой формат. Practice: `{version:1, startedOn, revision, nextReviewRevision, rules:[{effectiveFrom, targets}], reviews:[{gameId,date,note,createdAt,updatedAt,revision}], rewards:[{id,date,taskId,points,earnedAt}]}`. Targets: `{bullet,blitz,rapid,puzzles,reviews}`. Revision программы меняется при настройке правил; у заметок собственная revision, выдаваемая сохраняемым счётчиком nextReviewRevision, чтобы удаление и повторное создание не принимали старую правку. V2-восстановление обновляет версии правил и заметок, отклоняя черновики до замены. При системной дате раньше сохранённых тренировок операция отклоняется без потери записей.

`repository.transactPractice(update)` читает `{journal,practice,games,sync}` одной readwrite-транзакцией journal/games/historyMeta. Синхронный updater возвращает `{journal,practice}`; обе записи journal сохраняются вместе. Ответ с сохранёнными записями и прочитанными фактами возвращается после transaction complete. Ошибка отменяет обе записи; сеть внутри транзакции не используется.

Core:

- `initialPractice(journal,today)`, `getTargets(practice,date)`, `normalizeTargets(input)`.
- `configurePractice(practice,today,targets,expectedRevision)` → новое состояние, правила на завтра.
- `saveReview(practice,games,{gameId,note,expectedRevision},today,instant)` и `deleteReview(practice,{gameId,expectedRevision},today)`.
- `reconcilePractice({journal,practice,games},today,instant)` → `{journal,practice}`: создание программы, сегодняшняя цель задач, уникальные награды по известным фактам со дня запуска.
- `practiceSnapshot({journal,practice,games,sync},today)` → профиль, date, program, tasks, rewards, week, reviewOptions, reviews, coverage.

Snapshot: `program:{id,title,startedOn,revision,targets,pending:null|{effectiveFrom,targets}}`; `tasks:[{id,target,current,completed,source}]`, отключённые задания отсутствуют; `rewards:{totalXp,level,nextLevelXp,gainedToday}`; week — семь `{date,scheduled,completed}`; reviewOptions — 30 последних `{id,speed,result,createdAt}`; reviews — все собственные заметки; `coverage:{coverageStart,completedUntil,partial}`. Source: `games`, `manual`, `review`. Puzzles current равен target при отметке, иначе 0.

`createPracticeService({repository,now})` принимает `program.getSnapshot`, `program.configure {day,targets,expectedRevision}`, `program.saveReview {day,gameId,note,expectedRevision}`, `program.deleteReview {day,gameId,expectedRevision}`. Все изменения проверяют показанный день. Его `handleTraining(command,instant)` сохраняет прежние снимки training и ручные команды, но использует общую транзакцию и награды. `createServices` передаёт этот сервис в `createTrainingService`; самостоятельный legacy factory без него сохраняет прежний интерфейс.

После commit API и импорта интерфейс перечитывает программу локально. Награды автоматически восстанавливаются из сохранённых фактов при следующем чтении, если экран закрыт между сохранением партии и обновлением программы. Это отдельная восстанавливаемая операция; она не продвигает курсор API.

## Резервные копии

Новый экспорт v2: `{format:'lichess-training-backup',version:2,exportedAt,state:<legacy journal>,practice}`. Максимум 16 МиБ, до 10 000 правил и 50 000 наград. Уровень не хранится. Проверка нормализует только известные поля, даты, лимиты, уникальность ID, версии и профиль перед транзакцией.

V1 до 2 МиБ по-прежнему принимается: заменяет старый журнал отметок, сохраняет уже существующую новую программу и разборы, пересчитывает XP за отметки. При отсутствии новой программы она создаётся из восстановленного журнала. V2 заменяет журнал, программу, заметки и награды вместе. Games, ratings и sync metadata обе версии оставляют на месте. Диалог показывает состав замены до подтверждения. `training.previewImport` проверяет файл без записи.
