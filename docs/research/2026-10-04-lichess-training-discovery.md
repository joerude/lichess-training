Текущее предложение состава продукта и модулей находится в [архитектуре и плане](../architecture.md). Пользователь уточнил: сначала обсуждаем архитектуру продукта, затем переходим к обучению и реализации. Учебная последовательность ниже — исходная карта исследования.

## Цель

Персональная программа тренировок на Lichess: отслеживать историю игры, получать задания на партии, задачи и разборы, видеть выполнение и изменения в игре. Разработка проекта также должна помочь освоить браузерные расширения.

Пользователь выбрал главный результат через месяц: **освоить разработку браузерного расширения**. Учебные этапы должны давать работающий результат и знакомить с отдельными частями addons. Отслеживание прогресса и программы тренировок сохраняются как назначение проекта.

Первая платформа — **Firefox**, выбран пользователем. Обучение должно быть частью разработки: объяснение механизма → небольшое изменение → проверка в браузере → объяснение результата своими словами. Формат и темп ещё уточняются по опыту пользователя.

## Предлагаемый тренировочный цикл

**Задание → игра или упражнение → разбор → повторение → обзор недели.**

Задания «5 bullet», «5 blitz», «новые задачи», «разобрать партию» — доступные шаблоны, а не обязательный ежедневный набор. Нагрузку выбираем после обсуждения времени на тренировки.

Предлагается отделить выполнение программы от шахматных результатов: XP за выбранные действия; рейтинг и качество игры — отдельные показатели. Исторический импорт не начисляет новый тренировочный XP. Эти правила пока являются предложениями.

## Учебная последовательность

Это предложение порядка работы, исходя из выбранной учебной цели.

| Этап | Работающий результат | Тема для изучения |
|---|---|---|
| 0. Подготовка Firefox | Платформа выбрана; расширение загружается локально для разработки | Структура расширения, about:debugging и инструменты разработчика |
| 1. Первый addon | Кнопка расширения открывает страницу с одним заданием на день | Manifest и интерфейс расширения |
| 2. Сохранение прогресса | Выполнение задания отмечается вручную и сохраняется после повторного открытия интерфейса; есть экспорт данных | Storage, события, даты и восстановление состояния |
| 3. Собственная история | Импортируется lichess_dataset; повторы по ID исключены; видна статистика по контролям | Форматы данных и модель истории |
| 4. Автоматический учёт партий | Новые завершённые партии из API обновляют подходящие задания без повторного учёта | Permissions, HTTP, фоновые события и синхронизация |
| 5. Программы и геймификация | Несколько видов заданий, XP и обзор недели | Правила выполнения и начисления наград |
| 6. Интеграция задач | Проверен OAuth; новые задачи учитываются через API, повторы — отдельно; при необходимости добавлен виджет на сайте | Identity/OAuth и content scripts |

Предлагаемый первый учебный срез: открыть задание → отметить выполнение → закрыть и снова открыть интерфейс → увидеть сохранённое состояние. Автоматический счётчик партий добавляется на этапе 4; ручная отметка первого среза не выдаётся за проверку через API.

Для разработки Firefox позволяет временную загрузку через `about:debugging`. После перезапуска браузера временное расширение надо загрузить снова; проверку обычной установки и восстановления после перезапуска выделяем отдельно. [Mozilla: временная установка](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/).

## Ограничения, влияющие на программу

- API задач хранит не каждую попытку. Для повторений нужен отдельный учёт.
- Компьютерный анализ не подтверждает самостоятельный разбор: требуется собственная запись о выполнении.
- Для метрик качества надо показывать состав и размер проанализированной выборки.
- Фоновые процессы расширения могут завершаться; состояние и даты должны сохраняться.
- Разборы по своим партиям относятся к завершённым играм.

Первичные источники и подробные объяснения находятся в [технических основаниях](2026-10-04-lichess-training-evidence.md#что-позволяет-lichess).

## Порядок дальнейшего интервью

Обсуждаем по одному вопросу, с конкретными примерами.

1. Главный результат через месяц — **ответ получен: освоить разработку расширения**.
2. Первый браузер — **ответ получен: Firefox**.
3. Опыт JavaScript/TypeScript и веб-разработки — вопрос задан, ответ ожидается. Затем уточнить формат обучения.
4. Реальный бюджет времени на разработку и отдельно на шахматные тренировки.
5. Предпочтительный контроль и необходимость работы с несколькими устройствами.
6. Правило выполнения разбора и повторения задач.
7. Предпочтительная геймификация и дни отдыха.
8. Только личное использование или дальнейшее распространение.
