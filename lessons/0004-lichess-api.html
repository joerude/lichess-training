Кнопка → разрешение → HTTP

Проследи один запрос к Lichess и проверь, почему ошибка сети не стирает сохранённые партии.

15–20 минут практикиРабочее расширение 0.3.0Без токена

Твой результат: находишь в коде начало сетевой операции, читаешь её параметры в Firefox и объясняешь, что сохраняется после успешной порции. Это маршрут для твоей проверки: поведение окон разрешения и загрузки в реальном Firefox ещё нужно наблюдать.

Рабочий пример: разрешение начинается с клика

Открытие экрана и возвращение фокуса читают локальный снимок через sync.getSnapshot. Запрос к Lichess начинается кнопкой. Вот сокращённый обработчик из ui/sync.js:

runButton.addEventListener('click', () => {
  let permissionPromise;
  try {
    permissionPromise = permissions.request({
      origins: ['https://lichess.org/*'],
      data_collection: ['authenticationInfo'],
    });
  } catch (error) { permissionPromise = Promise.reject(error); }
  // Результат передаётся контроллеру:
  void controller.run(permissionPromise);
});

permissions.request вызывается прямо во время действия пользователя, до любого await. Сам ответ приходит позже через Promise — обещание результата. MDN: запрос разрешения.

Здесь два согласия: доступ к https://lichess.org/* и передача имени профиля sebajun777. Они объявлены необязательными в manifest.json. Категория Firefox authenticationInfo включает имена пользователей; она не означает, что этот запрос передаёт пароль. Mozilla: категории передаваемых данных.

Клик → разрешение → sync.nextBatch → фоновый сервис
  → GET → поток NDJSON → проверка всей порции
  → одна транзакция: партии + курсор → снимок экрана

Предскажи → наблюдай · 8 минут

  1. В Firefox 140+ открой about:debugging → This Firefox. Для уже загруженного расширения нажми Reload, сохраняя ID lichess-training@local. Если его нет, выбери Load Temporary Add-on и extension/manifest.json. Открой журнал из popup. Mozilla: установка и Reload.
  2. Если оригинальная история ещё не импортирована, сначала пройди сохранение из урока 03. Тогда начальная граница API будет 8 марта 2026 года: последняя известная партия минус семь дней. Так загрузка заполнит разрыв после датасета. С пустой историей окно начинается лишь за 30 дней до первого обновления. Уже сохранённая граница сама не меняется.
  3. Запомни число сохранённых партий и статус тренировки. Запиши прогноз: появится ли HTTP-запрос при открытии экрана? Что произойдёт при отказе в разрешении?
  4. В about:debugging нажми Inspect у расширения. В toolbox открой Network, очисти список и отфильтруй по api/games/user. Обнови вкладку журнала и верни ей фокус. Ожидается отсутствие запросов к API до клика. В Debugger можно открыть исходники. Mozilla: toolbox расширения.
  5. Нажми Подключить Lichess и сначала откажи. Ожидается сообщение об отказе, прежняя история и отсутствие запроса API. Если согласие уже дано, используй инструкцию ниже для повторения опыта.
  6. Нажми кнопку снова и разреши доступ. В Network открой запрос: метод GET, путь /api/games/user/sebajun777, параметры max=200, sort=dateAsc, since, until; заголовок Accept: application/x-ndjson. В успешном ответе каждая непустая строка — отдельный объект партии. Число новых партий заранее неизвестно.
  7. Один запуск загружает до пяти порций последовательно. Если появилась кнопка Продолжить загрузку, цикл ещё не закончен. Можно продолжить позже; начальная догрузка большого периода займёт больше времени, чем урок. Остановить после текущей порции сохраняет текущую порцию перед остановкой.
Разрешение уже дано: как проверить отказ

Дождись окончания загрузки. В Console именно toolbox расширения выполни отзыв двух необязательных разрешений:

await browser.permissions.remove({
  origins: ['https://lichess.org/*'],
  data_collection: ['authenticationInfo'],
});

Вернись в журнал, затем повтори отказ и согласие через кнопку. Отзыв не запрашивает партии и не удаляет историю. MDN: отзыв разрешений.

Что означает успешная порция

lichess-client.js делает анонимный GET с credentials: 'omit'. Он проверяет HTTP-статус, читает поток байтов, декодирует UTF-8 и собирает строки NDJSON: сетевой кусок может закончиться посреди строки. Только после полного чтения порция передаётся дальше. MDN: чтение потока; Lichess: экспорт партий.

sync-state.js проверяет порядок и границы времени всех строк; сохраняет только завершённые rated standard партии bullet/blitz/rapid своего профиля. app/sync.js передаёт проверенные партии и следующий курсор в saveSyncBatch. В repository.js они записываются одной транзакцией: ошибка отменяет всю эту порцию. Ранее сохранённые порции остаются.

Курсор — дата начала следующей порции. Верхняя граница until фиксируется для цикла. При 200 исходных строках нужен следующий запрос; при меньшем числе после полного чтения цикл завершён. Следующий новый цикл снова просматривает окно от сохранённой нижней границы: так можно увидеть партию, которая завершилась позже. Повторы объединяются по game ID.

«Сегодня» означает день начала партии по времени Бишкека. Пока весь период не загружен, счётчики могут быть неполными. API не отмечает тренировку и не начисляет XP. Исторический график Puzzles остаётся прежним; сегодняшние задачи ты по-прежнему отмечаешь вручную.

Самостоятельно · 4 минуты

Без готовой схемы найди в Debugger три места: где команда становится runtime.sendMessage, где fetch получает credentials: 'omit', где начинается транзакция для партий и курсора. Запиши файл и одну строку доказательства для каждого. Исходники можно читать и в редакторе.

Сверь после своей попытки

ui/client.js: runtime.sendMessage(command). data/lichess-client.js: вызов fetchImpl с credentials: 'omit'. data/repository.js: внутри saveSyncBatch транзакция ['games', 'historyMeta'], режим readwrite.

Теперь предскажи результат сбоя. Дождись окончания текущей загрузки, запомни число партий и поля «Полностью загружено до» и «Последняя завершённая загрузка периода». Отключи сетевое соединение компьютера, нажми кнопку загрузки и дождись ошибки. Ожидается: эти данные и отметка тренировки сохраняются. Верни сеть; продолжение начинается только по твоему клику. Ошибка не считается пустой успешной порцией.

Подсказка после попытки

Границы сетевых кусков произвольны. Общая транзакция не позволяет продвинуть курсор без партий. Пять порций ограничивают один запуск; до конца окна могут оставаться ещё порции.

Повтори завтра · 2 минуты

Закрой памятку и восстанови путь клик → разрешение → сообщение → HTTP → проверка → транзакция. Затем найди эти места снова. Скажи, что случится с партией, начавшейся внутри окна, но завершившейся после прежней загрузки.

Резервная копия журнала содержит только отметки тренировок; история и состояние загрузки в неё не входят. Если что-то осталось неясным, задай вопрос по конкретной строке кода или своему наблюдению в Firefox.
