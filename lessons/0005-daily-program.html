Одна задача — одна награда

Проверь ежедневную программу и измени расчёт уровня, сохранив заработанные XP.

15–20 минут практикиВерсия 0.4.0Данные → правила → экран

Результат занятия: объясняешь, как стабильный ID предотвращает повторную награду, и самостоятельно меняешь вычисляемый уровень. Проверки проекта уже есть; свою практику в Firefox ты выполняешь отдельно.

Программа и её факты

Начальный шаблон — 5 Bullet, 5 Blitz, 10 задач, 1 собственный разбор. Игровые цели используют сохранённые завершённые рейтинговые стандартные партии. Задачи отмечаешь вручную. Для разбора открываешь партию на Lichess и сохраняешь собственный вывод здесь.

Старый датасет даёт исходную историю и партии для разбора. XP начинается с дня запуска новой программы. Разбор мартовской партии, сохранённый сегодня, засчитывается сегодня; его последующая правка сохраняет первоначальную дату.

Факты и награды хранятся отдельно. По фактам вычисляется выполнение. Каждое выполненное задание даёт 20 XP; уровень вычисляется из суммы наград.

Завершённые партии + отметка задач + собственные заметки
  → выполнение заданий по дню
  → уникальные награды
  → сумма XP → уровень → интерфейс

Рабочий пример: стабильный ID

В practice-engine.js функция reconcilePractice собирает награды в Map — набор значений с уникальными ключами. Для одного задания один ключ:

const id = `${program.startedOn}:${date}:${task.id}`;
rewards.set(id, previous.get(id) ?? {
  id, date, taskId: task.id, points: 20, earnedAt,
});

Например, 2026-10-06:2026-10-06:puzzles. Повторное чтение создаёт тот же ID и использует прежнюю награду. Количество открытий popup в ключ не входит. Такое повторяемое действие без нового эффекта называют идемпотентным.

Ручные награды пересчитываются: отмена отметки задач убирает её XP, повторная отметка возвращает одну награду. Правка текста разбора не создаёт новое задание; удаление заметки может снять награду того дня, если оставшихся разборов меньше нормы.

Предскажи → проверь · 7 минут

  1. Сохрани текущую копию прогресса. В about:debugging#/runtime/this-firefox нажми Reload у расширения с тем же ID и открой журнал. Если addon ещё не загружен, выбери extension/manifest.json через Load Temporary Add-on. Mozilla: временная установка.
  2. Запомни XP и статус задач. Предскажи, что изменится после отметки, трёх обновлений и повторного открытия popup.
  3. Если задачи ещё не отмечены, реши их на Lichess и отметь выполнение. Ожидается +20 XP. Обнови три раза: повторных наград нет. Если отметка уже была, начни с отмены: ожидается −20 XP; повторная отметка возвращает 20.
  4. При импортированной истории выбери завершённую партию, открой её и сохрани один вывод. При норме 1 разбор это выполнит задание дня. Исправь заметку: XP и дата разбора прежние. Если сегодняшний разбор уже был, новая заметка не даёт вторую награду за то же задание.
  5. В настройке программы измени одну норму и сохрани. Ожидается правило на завтра; сегодняшняя цель прежняя. Сохрани новую резервную копию и открой JSON в редакторе: найди practice.rules, practice.reviews, practice.rewards.

Игровые числа могут быть неполными, пока API ещё загружается. Известные 5 из 5 доказывают выполнение; 3 из 5 не доказывают отсутствие других партий. Восстановленная награда за игры сохраняет XP даже до повторного импорта этих игр, но сами счётчики и статус задания показывают доступные факты.

Сохранить отметку и XP вместе

app/practice.js готовит оба состояния внутри transactPractice. repository.js сохраняет ключи state и practice в store journal одной транзакцией. Ошибка отменяет обе записи.

Успех одной операции put ещё не означает завершение всех записей. Repository отвечает после события complete всей транзакции. MDN: complete. Область транзакции включает journal, games и historyMeta, чтобы правила читали согласованные факты. MDN: область и режим транзакции.

Загрузка API сохраняет партии и курсор своей транзакцией. Затем программа пересчитывает награды локально. Если экран закрылся между этими действиями, следующее чтение увидит сохранённые партии и восстановит недостающие награды.

Самостоятельное изменение · 5 минут

Предскажи уровень при 100 XP: сейчас это 2. Если один уровень потребует 200 XP, что изменится в данных резервной копии?

  1. В practiceSnapshot найди totalXp, level и nextLevelXp.
  2. Временно измени расчёт так, чтобы один уровень требовал 200 XP. Найди все связанные числа в этих двух выражениях. Не меняй размер награды 20 XP и записи practice.rewards.
  3. В терминале из корня выполни команду ниже; сравни результат с прогнозом. Затем Reload addon и посмотри уровень в журнале.
  4. Верни порог 100 и повтори проверку. Итоговая рабочая программа снова использует исходные правила.
node --test tests/practice-engine.test.js
Подсказка после попытки

level: 1 + Math.floor(totalXp / 200); nextLevelXp: 200 - totalXp % 200. При 100 XP уровень будет 1 и до следующего останется 100. Тест исходного порога должен сообщить различие; после возврата 100 — пройти. Накопленные XP и журнал наград не меняются, потому что уровень вычисляется, а не хранится.
