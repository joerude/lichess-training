# Lichess Training

Персональные программы тренировок на Lichess: задания на игры, задачи и разборы, история прогресса и геймификация. Проект также служит практикой разработки браузерных расширений.

Рабочая версия **0.2.0 для Firefox**: задание на 10 задач с собственной отметкой, popup, история последних семи дней, резервная копия отметок и импорт собственной истории партий со статистикой и графиком рейтинга. Аккаунт — `sebajun777`, часовой пояс программы — `Asia/Bishkek`. Главный результат через месяц — освоить разработку браузерного расширения на полезном шахматном проекте.

Следующие этапы — новые партии из API, несколько заданий, собственные разборы и XP.

## Запустить в Firefox

Нужен Firefox desktop 140 или новее. Для временной загрузки Node не требуется.

1. Открой `about:debugging#/runtime/this-firefox`.
2. Нажми **Load Temporary Add-on…** / «Загрузить временное дополнение».
3. Выбери `/home/joerude/lichess-training/extension/manifest.json`.
4. Найди «Шахматный журнал» в меню расширений Firefox, открой popup и нажми переход на основной экран.

Задачи решаются на Lichess; выполнение подтверждаешь вручную после тренировки. Прогресс хранится в IndexedDB. Экспорт JSON содержит отметки тренировок; восстановление после предварительного просмотра заменяет этот журнал. История партий хранится отдельно и сохраняется при восстановлении отметок.

Временный addon исчезает из установленных после перезапуска Firefox: загрузи его заново. Подпись и постоянная установка запланированы отдельно. [Mozilla: временная установка и Reload](https://extensionworkshop.com/documentation/develop/temporary-installation-in-firefox/).

## Импортировать свой датасет

На основном экране в разделе истории выбери:

1. `/home/joerude/Desktop/lichess_dataset/games/games_raw.ndjson` — партии.
2. `/home/joerude/Desktop/lichess_dataset/rating_history.json` — необязательная история рейтингов.
3. Нажми **Проверить файлы**, затем **Сохранить историю**.

Проверка показывает 6 430 строк, 6 429 уникальных партий, один повтор и 474 точки рейтинга. После сохранения: Bullet — 5 917, Blitz — 345, Rapid — 167. Повторное сохранение добавит 0 партий. Таблица показывает победы/поражения/ничьи, долю побед, покрытие компьютерным анализом и последний рейтинг; график переключается между Bullet/Blitz/Rapid/Puzzles.

Датасет заканчивается 15 марта 2026 года. Это исходная история, которую можно заново импортировать из тех же файлов. Она не создаёт отметки сегодняшних тренировок. Без файла рейтингов график строится по последнему известному рейтингу после партии за день по времени Бишкека; Puzzles требует отдельного JSON. Некорректная строка или другой профиль отклоняют весь файл до записи. Размер партий ограничен 20 МиБ и 100 000 непустых строк, рейтингов — 1 МиБ.

## Разработка и проверки

Node 22+ и npm нужны для тестов и упаковки. В корне проекта:

```sh
npm ci
npm test
npm run lint:addon
npm run build:addon
npm run inspect:dataset -- /home/joerude/Desktop/lichess_dataset/games/games_raw.ndjson /home/joerude/Desktop/lichess_dataset/rating_history.json
```

`web-ext` создаёт ZIP в `dist/`; это неподписанный пакет для разработки. Он не предназначен для обычной постоянной установки в Firefox. В ZIP входит только каталог `extension/`, без датасета, инструментов Node и уроков.

Код написан обычными ES modules без сборщика. `background.js` получает команды страниц; `app/services.js` направляет их в сервис тренировок или истории. Чистые модули нормализуют партии и рассчитывают статистику. `data/repository.js` сохраняет journal отдельно от games, ratings и historyMeta. Локальные данные не отправляются в сеть этой версией; переход на Lichess открывает обычную страницу сайта.

Автоматические тесты используют реальные правила, сервис и repository с `fake-indexeddb` на границе браузерного хранилища. `web-ext lint` проверяет совместимость addon. [Ручная проверка Firefox](docs/manual-qa.md) остаётся отдельной: подключённого браузера в текущей сессии нет.

[Проверки и ограничения](docs/verification.md) описывают автоматические тесты, проверку исходного датасета и упаковки; там же описан известный audit-пункт в инструментах разработки. [Ревью этапа 1](docs/reviews/2026-10-04-stage1.md) завершено без открытых замечаний.
