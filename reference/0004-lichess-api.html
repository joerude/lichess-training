HTTP и разрешение

  • GET https://lichess.org/api/games/user/sebajun777, Accept: application/x-ndjson, credentials: 'omit'. Токен для этой публичной выгрузки не нужен.
  • since и until — миллисекунды Unix; sort=dateAsc, max=200, ongoing=true, finished=true. Отбор завершённых rated standard bullet/blitz/rapid выполняется локально.
  • origins: ['https://lichess.org/*'] разрешает обращение к хосту. data_collection: ['authenticationInfo'] относится к передаче имени профиля. Отказ оставляет журнал доступным.
  • NDJSON — один JSON-объект на непустую строку. Сетевые куски не обязаны совпадать со строками; остаток строки переносится до следующего куска.
  • Лимиты этого клиента: 200 непустых строк, 8 МиБ, 30 секунд на запрос вместе с чтением. HTTP 429 сохраняет паузу минимум на минуту, с учётом более долгого Retry-After. Автоматического повторного запроса после ошибки нет.

Окно и курсор

  • coverageStart — постоянная нижняя граница по началу партий: последняя известная партия минус семь дней, либо последние 30 дней при пустой истории. Сначала импортируй исходный датасет, чтобы охватить разрыв с марта.
  • cycleUntil — фиксированная верхняя граница незавершённого цикла. Окно [since, until): начало включено, конец исключён.
  • nextSince — начало следующей порции. При 200 строках это последний исходный createdAt включительно; повторы на границе объединяются по ID. Если дата не продвигается, получаем ошибку без объявления полноты.
  • completedUntil и lastSuccessAt меняются после полного чтения порции с менее чем 200 строками. Сохранение заполненной порции ещё не означает конец цикла.
  • Новый цикл снова сканирует всё окно от coverageStart, чтобы увидеть поздно завершённые партии. Начавшиеся раньше этой границы остаются вне API-окна.

Это алгоритм нашего клиента. Границы по createdAt подтверждены в исходниках Lichess; включение начала и исключение конца — в реализации диапазона.

Что сохраняется

Вся порция сначала проверяется. Партии и курсор сохраняются вместе; ошибка отменяет эту транзакцию. Совместимые сведения той же партии обновляются по ID, пропущенные поля не стирают прежние. Уже сохранённые порции переживают остановку и закрытие экрана; продолжение запускается вручную.
